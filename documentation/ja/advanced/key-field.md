# フィールド制約

フィールド制約はフィールド値のルールを制限し、データの一意性と整合性を確保するために使用されます。

## 一意制約（unique）

一意制約はフィールド値が重複できないことを保証します。

### マーカー方法

| 簡易記法   | メタ属性記法         | 説明         |
| ------ | ------------- | ---------- |
| `@フィールド名` | `フィールド名 @unique` | 一意フィールド、値が重複不可 |

### 例

| @dict     | 名前     | メール                     |
| --------- | ------ | ---------------------- |
| user\_id  | name   | @email                 |
| string    | string | string                 |
| user\_001 | 田中     | <tanaka@example.com> |
| user\_002 | 鈴木     | <suzuki@example.com>     |

- `@email` - メールフィールドの値が重複不可

## 主キー制約（primary）

主キーはテーブル内の各行データを一意に識別するためのフィールドです。

### デフォルトルール

- **最初の列が自動的に主キーとして扱われる**、追加のマーカー不要

### マーカー方法

| 簡易記法    | メタ属性記法          | 説明            |
| ------- | -------------- | ------------- |
| `@@フィールド名` | `フィールド名 @primary` | 主キーフィールド、値が一意で主キーとして機能 |

### 例

| @dict      | 名前     |
| ---------- | ------ |
| @@item\_id | name   |
| string     | string |
| sword\_001 | 鉄の剣     |
| sword\_002 | 鋼の剣    |

- `@@item_id` - 主キーフィールド、値が一意

## 複合制約

複数のフィールドの組み合わせが一意でなければならない場合、複合制約を使用できます。型マーカーの後に `@unique(field1, field2)` を追加：

| @dict @unique(class, level) | 職業      | レベル    |
| --------------------------- | ------- | ----- |
| id                          | class   | level |
| string                      | string  | i32   |
| warrior\_001                | warrior | 10    |
| warrior\_002                | warrior | 20    |
| mage\_001                   | mage    | 10    |

上記の例では、`職業 + レベル` の組み合わせが一意である必要がありますが、職業またはレベル単独では重複可能です。

> ⚠️ **警告**：複合一意制約を使用した場合、その表を参照する `&T` も複合キーを入力する必要があります。一部のゲームエンジンは複合キーをサポートしていないため、慎重に使用してください。

## 制約要件

- 主キー値は一意である必要があります
- 主キー値は null にできません
- 各テーブルに設定できる主キーは1つだけです
- 一意フィールド値は重複できません
