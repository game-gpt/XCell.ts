## 高度な設定オプション

XCell の設定ファイル `XCell.toml` は豊富な設定オプションを提供し、ツールの動作を柔軟にカスタマイズできます。

### 基本設定構造

完全な `XCell.toml` 設定ファイルには、以下の主要部分が含まれます：

```toml
version = "0.0.0"

exclude = ""
include = "*.xlsx"

line.field = 1
line.type = 2
line.comment = 3
line.data = 4

[type.bool]
accept = ["true", "√"]
reject = ["false", "x"]

[type.string]

[merge]
```

### バージョン管理設定

```toml
version = "0.0.0"
```

- **version**: 現在のプロジェクトのバージョン番号、生成されたコードとデータファイルのバージョンを識別するために使用

### ファイル包含/除外設定

```toml
exclude = ""
include = "*.xlsx"
```

- **include**: 含める Excel ファイルパターン、ワイルドカードをサポート
- **exclude**: 除外する Excel ファイルパターン、include より優先度が低い

例：
```toml
include = "tables/**/*.xlsx"
exclude = "tables/temp/*.xlsx"
```

### テーブル行設定

```toml
line.field = 1
line.type = 2
line.comment = 3
line.data = 4
```

- **line.field**: フィールド名が存在する行番号（1から開始）
- **line.type**: 型宣言が存在する行番号
- **line.comment**: コメントが存在する行番号
- **line.data**: データ開始行番号

### 型設定

#### ブール型設定

```toml
[type.bool]
accept = ["true", "√"]
reject = ["false", "x"]
```

- **accept**: true として認識される値のリスト
- **reject**: false として認識される値のリスト

#### 文字列型設定

```toml
[type.string]
# 拡張設定可能
```

## 表結合ルールの詳細

表結合ルールを使用すると、複数の Excel 表を1つに結合でき、行または列単位での結合をサポートします。

### 表結合ルール設定

表結合ルールは `[merge]` セクションで設定し、各ルールは一意の番号で識別されます。

```toml
[merge.10001]
mode = "row"
input = "Language_CN*"
target = "Language_CN"

[merge.10002]
mode = "row"
input = "Language_EN*"
target = "Language_EN"

[merge.20001]
mode = "column"
input = "Language*"
target = "Language"
```

### 結合モード

#### 行結合モード (row)

```toml
mode = "row"
```

行結合は複数の表のデータ行を1つの表に結合します。以下に適用：
- 同一表のデータ量が多く、分割管理が必要
- 多言語データの分離管理

ディレクトリ構造例：
```
LanguageTable/
  - CN/
    - Language_CN_UI.xlsx
    - Language_CN_Item.xlsx
  - EN/
    - Language_EN_UI.xlsx
    - Language_EN_Item.xlsx
```

#### 列結合モード (column)

```toml
mode = "column"
```

列結合は複数の表の列を1つの表に結合します。以下に適用：
- 複数列のデータを異なるファイルに分散
- 異なるチームが同じ表の異なる部分を共同編集

### 表結合ルールパラメータ

- **mode**: 結合モード、`row` または `column`
- **input**: 入力ファイルパターン、ワイルドカードをサポート
- **target**: ターゲットテーブル名

### 表結合実行順序

ルール番号は表結合の実行順序を決定し、番号が小さいほど早く実行されます。推奨：
- 行結合は 10000-19999 の範囲を使用
- 列結合は 20000-29999 の範囲を使用
- その他のカスタムルールはより大きな番号を使用

## パフォーマンス最適化のヒント

### 大きな表の処理最適化

#### 1. 大きな表を適切に分割

- 大きな表を機能またはモジュールごとに分割
- ビルド時に結合ルールを使用して結合
- 開発時の保守性とランタイムのパフォーマンスを維持

#### 2. バイナリフォーマットの使用

- バイナリフォーマットの読み込み速度が最速
- 本番環境ではバイナリフォーマットの使用を推奨
- 開発環境では XML/JSON を使用してデバッグを容易に

### 増分更新の最適化

#### 1. 監視モード

監視モードを使用：

```bash
xcell.exe --watch
```

監視モードの特徴：
- 変更されたファイルのみ再生成
- 開発効率を大幅に向上
- リアルタイムプレビューをサポート

#### 2. 監視の適切な設定

適切な include/exclude パターンを設定し、監視ファイル数を削減。

### メモリ最適化

#### 1. 必要な表のみ読み込み

エンジンの API に応じて、現在のシーンまたは機能に必要な表のみを読み込み、一度にすべての表を読み込まないようにする。

#### 2. 適時アンロード

不要になった表は適時アンロードしてメモリを解放。

### ビルド最適化

#### 1. 並列処理

XCell は複数ファイルの並列処理をサポートし、ビルド速度を大幅に向上させます。

#### 2. キャッシュメカニズム

キャッシュを適切に使用し、重複処理を回避。
