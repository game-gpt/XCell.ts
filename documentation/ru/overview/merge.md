# Правила слияния таблиц

XCell поддерживает слияние нескольких таблиц в одну. Через правила слияния вы можете гибко управлять сложными структурами данных.

## Соглашение об именовании

- **Именование PascalCase** (например, `ItemWeapon`, `ItemArmor`): Независимые таблицы, не участвующие в слиянии
- **Именование с подчёркиванием** (например, `Item_Weapon`, `Item_Armor`): Автоматически сливаются в таблицу `Item`

## Пример

| Имя файла | Поведение |
|----------|----------|
| `ItemWeapon.xlsx` | Независимая таблица, генерирует `ItemWeapon` |
| `ItemArmor.xlsx` | Независимая таблица, генерирует `ItemArmor` |
| `Item_Weapon.xlsx` | Сливается в `Item` |
| `Item_Armor.xlsx` | Сливается в `Item` |
| `Item_Consumable.xlsx` | Сливается в `Item` |

## Логика слияния

- Таблицы с одинаковой структурой будут объединены
- **Дублирование ID вызовет ошибки** (порядок слияния зависит от хранения на диске, не является фиксированным)
- Окончательный вывод будет отсортирован по ID

## Варианты использования

### Сценарий: Управление таблицами по типу

Предположим, у вас есть следующие таблицы предметов:
- `Item_Weapon.xlsx` - Конфигурация оружия
- `Item_Armor.xlsx` - Конфигурация брони
- `Item_Consumable.xlsx` - Конфигурация расходуемых предметов

Они автоматически сольются в таблицу `Item`.

## Примечания

- Объединяемые таблицы должны иметь одинаковую структуру (одинаковые имена столбцов и типы)
- При конфликте первичных ключей данные из более позднего файла перезапишут данные из более раннего
- Рекомендуется создавать резервные копии исходных файлов перед выполнением операций слияния
- **`Language` — зарезервированное имя таблицы**, все таблицы языков сливаются в Language, не используйте это имя
