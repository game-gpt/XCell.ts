# Ограничения полей

Ограничения полей — это правила, используемые для ограничения значений полей, обеспечивающие уникальность и целостность данных.

## Ограничение уникальности (unique)

Ограничение уникальности гарантирует, что значения поля не могут дублироваться.

### Способ маркировки

| Сокращение | Нотация мета-атрибута | Описание |
| --------- | ----------------------- | ----------- |
| `@field_name` | `field_name @unique` | Уникальное поле, значения не могут дублироваться |

### Пример

| @dict | Name | Email |
| ----- | ---- | ----- |
| user\_id | name | @email |
| string | string | string |
| user\_001 | John | <john@example.com> |
| user\_002 | Jane | <jane@example.com> |

- `@email` - Значения поля Email не могут дублироваться

## Ограничение первичного ключа (primary)

Первичный ключ — это поле, используемое для уникальной идентификации каждой строки данных в таблице.

### Правило по умолчанию

- **Первый столбец автоматически считается первичным ключом**, дополнительная маркировка не требуется

### Способ маркировки

| Сокращение | Нотация мета-атрибута | Описание |
| --------- | ----------------------- | ----------- |
| `@@field_name` | `field_name @primary` | Поле первичного ключа, значения уникальны и являются первичным ключом |

### Пример

| @dict | Name |
| ----- | ---- |
| @@item\_id | name |
| string | string |
| sword\_001 | Железный меч |
| sword\_002 | Стальной меч |

- `@@item_id` - Поле первичного ключа, значения уникальны

## Составное ограничение

Когда комбинация нескольких полей должна быть уникальной, можно использовать составные ограничения. Добавьте `@unique(field1, field2)` после маркера типа:

| @dict @unique(class, level) | Class | Level |
| --------------------------- | ----- | ----- |
| id | class | level |
| string | string | i32 |
| warrior\_001 | warrior | 10 |
| warrior\_002 | warrior | 20 |
| mage\_001 | mage | 10 |

В приведённом выше примере комбинация `Class + Level` должна быть уникальной, но отдельные значения class или level могут дублироваться.

> ⚠️ **Предупреждение**: Если используется составное ограничение уникальности, то ссылки `&T` на эту таблицу также должны заполнять составные ключи. Некоторые игровые движки не поддерживают составные ключи, используйте с осторожностью.

## Требования к ограничениям

- Значения первичного ключа должны быть уникальными
- Значения первичного ключа не могут быть null
- Каждая таблица может иметь только один первичный ключ
- Значения уникальных полей не могут дублироваться
