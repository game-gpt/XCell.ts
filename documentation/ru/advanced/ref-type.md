# Ссылочные типы

## Зачем нужны ссылочные типы?

При настройке игровых данных часто возникают следующие проблемы:

**Неправильный ID**

В таблице предметов вы указали ID качества `comon`, но в таблице качества фактически `common`, пропущена одна буква `m`. Такого рода опечатки трудно обнаружить, и проблемы возникнут при запуске игры.

**ID изменён, ссылка не синхронизирована**

Таблица качества изменила `common` на `normal`, но таблица предметов всё ещё использует `common`. В результате предметы не могут найти соответствующую конфигурацию качества.

---

Ссылочные типы предназначены для решения этих проблем. XCell автоматически проверяет правильность ссылок, обеспечивая:
- Указанные ID должны существовать в целевой таблице
- Если ID не существует, будет немедленно выдана ошибка

## Базовый формат

- `&T` - Ссылка на таблицу T

## Что такое ссылка?

Проще говоря, ссылка — это «связь, указывающая на строку данных в другой таблице».

Например: В таблице предметов вам нужно записать «какому качеству принадлежит этот предмет», в этом случае вы можете использовать ссылочный тип для указания на таблицу качества.

## Пример

### Шаг 1: Создание таблицы качества

Сначала создайте таблицу качества:

| @dict | Color | Description |
| ----- | ----- | ----------- |
| quality_id | color | desc |
| string | string | string |
| common | #FFFFFF | Обычное качество |
| rare | #00FFFF | Редкое качество |
| epic | #FF00FF | Эпическое качество |

### Шаг 2: Создание таблицы предметов (ссылка на таблицу качества)

Поле `quality_id` в таблице предметов использует тип `&Quality`, указывая на то, что оно ссылается на таблицу качества:

| @dict | Name | Quality | Attack |
| ----- | ---- | ------- | ------ |
| item_id | name | quality_id | attack |
| string | string | &Quality | i32 |
| sword_001 | Железный меч | common | 10 |
| sword_002 | Стальной меч | rare | 50 |
| sword_003 | Драконий меч | epic | 200 |

## Частые варианты использования

| Сценарий | Описание |
| -------- | ----------- |
| Предмет → Качество | К какому уровню качества принадлежит предмет |
| Снаряжение → Персонаж | Какой персонаж может экипировать снаряжение |
| Навык → Класс | К какому классу относится навык |
| Монстр → Таблица дропа | Из какой таблицы дропа выпадает монстр |

## Типы таблиц, на которые можно ссылаться

Следующие типы таблиц могут быть объектами ссылок:

| Тип | Описание |
| ---- | ----------- |
| Таблица dict | Строковый первичный ключ, например ID предмета, ID навыка |
| Таблица list | Целочисленный первичный ключ, например номер монстра, номер предмета |
| Таблица language | Ключ языка, формат `group_name/language_key`, например `&Language` |

### Специальный формат ссылок на таблицу языков

При ссылке на таблицу языков формат заполняемого значения — `group_name/language_key`:

| @dict | Name | Tip Text |
| ----- | ---- | -------- |
| item_id | name | tip |
| string | string | &Language |
| sword_001 | Железный меч | ui/item_tip_001 |

Следующие типы **не могут быть объектами ссылок**:

| Тип | Причина |
| ---- | ------ |
| Таблица enum | Перечисления — это фиксированные варианты, а не таблицы данных |
| Таблица class | Глобальная конфигурация имеет только один экземпляр |
| Базовые типы | i32, string и др. — это типы значений, а не таблицы |

## Ссылки во вложенных типах

Ссылочные типы могут комбинироваться с другими типами для формирования более сложных структур данных.

### Массив ссылок

Когда вам нужно сослаться на несколько целей, можно использовать массив ссылок:

| Формат | Описание |
| ------ | ----------- |
| `[&T]` | Массив ссылок, хранит несколько первичных ключей целевой таблицы |

**Пример: Таблица дропа со ссылкой на несколько предметов**

| @dict | Name | Drop Items |
| ----- | ---- | ---------- |
| drop_id | name | items |
| string | string | [&Item] |
| drop_001 | Стартовый набор | sword_001, potion_001 |
| drop_002 | Награда элиты | sword_002, armor_001, gem_001 |

### Другие вложенные комбинации

| Формат | Описание |
| ------ | ----------- |
| `[&T]` | Массив ссылок |
| `Vec<&T>` | Вектор ссылок |
| `HashMap<string, &T>` | Отображение строки в ссылку |

## Валидация ссылок

XCell автоматически проверяет правильность ссылок:

- ✅ Указанные ID должны существовать в целевой таблице
- ✅ Нельзя указать несуществующие ID
- ✅ Циклические ссылки будут обнаружены и сообщены

## Генерация кода

### TypeScript (Cocos, Laya)

```typescript
export class Item {
    public itemId: string;
    public name: string;
    public qualityId: string;  // Хранит значение первичного ключа
    public attack: number;
}

export class ItemTable {
    private _items: Map<string, Item>;
    private _qualityTable: QualityTable;

    public getQuality(itemId: string): Quality | undefined {
        const item = this._items.get(itemId);
        if (item) {
            return this._qualityTable.get(item.qualityId);
        }
        return undefined;
    }
}
```

### C# (Unity, Godot)

```csharp
public class Item
{
    public string ItemId;
    public string Name;
    public string QualityId;  // Хранит значение первичного ключа
    public int Attack;
}

public class ItemTable
{
    private Dictionary<string, Item> _items;
    private QualityTable _qualityTable;

    public Quality GetQuality(string itemId)
    {
        if (_items.TryGetValue(itemId, out var item))
        {
            return _qualityTable.Get(item.QualityId);
        }
        return null;
    }
}
```

## Примечания

- Целевая таблица ссылки должна существовать
- Целевая таблица должна быть типа dict, list или language
- Таблицы enum и class не могут быть объектами ссылок
- Базовые типы (i32, string и др.) не могут быть объектами ссылок
- Рекомендуется использовать PascalCase для имён таблиц, например `&QualityTable`
