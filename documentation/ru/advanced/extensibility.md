## Пользовательская система типов

XCell предоставляет гибкую систему типов, поддерживающую множество встроенных типов данных и позволяющую разработчикам создавать новые типы данных.

### Обзор встроенных типов

XCell поддерживает следующие встроенные типы:

| Категория типов | Поддерживаемые типы                                                                                                            |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Логические       | `bool`, `boolean`                                                                                                          |
| Целые числа       | `byte`/`i8`, `short`/`i16`, `int`/`i32`, `long`/`i64`, `sbyte`/`u8`, `ushort`/`u16`, `uint`/`u32`, `ulong`/`u64`          |
| Десятичные       | `float`/`f32`, `double`/`f64`, `decimal`/`d128`/`f128`                                                                     |
| Строковые        | `string`                                                                                                                   |
| Специальные типы | `color`/`colour`, `color32`, `time`/`date`/`datetime`                                                                      |
| Векторы/Массивы  | `v2`/`vec2`, `v3`/`vec3`, `v4`/`vec4`, `q4`/`quaternion`                                                                   |
| Перечисления          | Пользовательские типы перечислений                                                                                                          |

### Архитектура системы типов

Ядро системы типов XCell расположено в модуле `xcell-types`, в основном содержит следующие компоненты:

- `XCellTyped`: Перечисление типов, определяющее все поддерживаемые типы данных
- `TypeMetaInfo`: Метаданные типа, содержащие информацию о конфигурации типа
- `XCellValue`: Значение типа, хранящее разобранные данные
- Различные дескрипторы типов: такие как `IntegerDescription`, `DecimalDescription` и др.

### Шаги реализации пользовательского типа

Чтобы добавить пользовательский тип, выполните следующие шаги:

#### 1. Создание модуля описания типа

Создайте новый модуль типа в директории `projects/xcell-types/src/`, например `my_type/mod.rs`:

```rust
use serde::{Deserialize, Serialize};
use xcell_errors::XResult;
use crate::value::XCellValue;

#[derive(Debug, Clone, Default, Serialize, Deserialize)]
pub struct MyTypeDescription {
    pub default: Option<String>,
}

impl MyTypeDescription {
    pub fn parse_cell(&self, cell: &str) -> XResult<XCellValue> {
        todo!("Реализуйте логику разбора ячеек")
    }
}
```

#### 2. Расширение перечисления XCellTyped

Расширьте перечисление `XCellTyped` в `projects/xcell-types/src/typing/mod.rs`:

```rust
pub enum XCellTyped {
    // ... существующие типы ...
    MyType(Box<MyTypeDescription>),
}
```

#### 3. Реализация разбора типа

Добавьте логику разбора типа в `projects/xcell-types/src/typing/parser.rs`:

```rust
impl XCellTyped {
    pub fn parse(input: &str, info: &TypeMetaInfo) -> Self {
        let normed = Self::norm_typing(input);
        match normed.as_str() {
            // ... существующие типы ...
            "mytype" | "my_type" => info.my_type.clone().into(),
            _ => XCellTyped::parse_complex(input, &normed, info),
        }
    }
}
```

#### 4. Обновление TypeMetaInfo

Обновите структуру `TypeMetaInfo` в `projects/xcell-types/src/typing/mod.rs`:

```rust
#[derive(Debug, Clone, Default, Serialize)]
pub struct TypeMetaInfo {
    // ... существующие поля ...
    pub my_type: MyTypeDescription,
}
```

#### 5. Добавление поддержки генерации кода

Добавьте логику генерации кода для нового типа в `projects/xcell-types/src/codegen/`, обеспечив корректные определения типов для целевых языков (например, C#).

## Расширение генераторов кода

XCell поддерживает несколько целей генерации кода, включая Unity C#, бинарные файлы, XML, JSON и др. Вы можете расширить эти генераторы или создать новые.

### Архитектура генерации кода

Генерация кода в основном реализована в модуле `xcell-core/src/codegen/`:

- `binary/`: Генерация бинарного формата
- `readable/`: Генерация читаемого формата (XML, JSON)
- `unity/`: Генерация кода Unity C#

### Расширение генератора кода Unity

Генератор кода Unity — один из наиболее часто используемых генераторов. Вот шаги для его расширения:

#### 1. Просмотр существующих шаблонов

Генерация кода Unity использует файлы шаблонов, расположенные в директории `projects/xcell-core/templates/`:

- `BuildClass.cs`: Шлон таблицы Class
- `BuildDictionary.cs`: Шаблон таблицы Dictionary
- `BuildEnumerate.cs`: Шаблон таблицы Enum
- `BuildLanguage.cs`: Шаблон таблицы Language
- `BuildManager.cs`: Шаблон менеджера

#### 2. Изменение или создание шаблонов

Измените существующие шаблоны или создайте новые файлы шаблонов по необходимости.

#### 3. Обновление конфигурации UnityCodegen

Обновите конфигурацию в `projects/xcell-core/src/config/unity/mod.rs`:

```rust
#[derive(Debug, Clone)]
pub struct UnityCodegen {
    // ... существующие поля ...
    pub my_custom_option: bool,
}
```

#### 4. Реализация логики генерации

Реализуйте конкретную логику генерации в `projects/xcell-core/src/codegen/unity/`.

### Создание нового генератора кода

Чтобы создать совершенно новый генератор кода, выполните следующие шаги:

#### 1. Создание модуля генератора

Создайте новый модуль в директории `projects/xcell-core/src/codegen/`, например `cocos/mod.rs`:

```rust
use xcell_errors::XResult;
use crate::config::ProjectConfig;

pub struct CocosCodegen {
    // Поля конфигурации
}

impl CocosCodegen {
    pub fn write(&self, config: &ProjectConfig) -> XResult<()> {
        todo!("Реализуйте логику генерации кода Cocos")
    }
}
```

#### 2. Интеграция в систему конфигурации

Добавьте параметры конфигурации для нового генератора в `ProjectConfig`.

#### 3. Подключение к рабочему процессу

Вызовите новый генератор в `WorkspaceManager::write_unity()` или аналогичных методах.

## Руководство по разработке плагинов

XCell поддерживает расширение функциональности через систему плагинов. Плагины могут добавлять новые типы таблиц, пользовательскую логику валидации или расширять возможности генерации кода.

### Архитектура плагинов

Система плагинов основана на системе типажей Rust, основные интерфейсы включают:

- Типаж обработчика таблиц
- Типаж валидатора
- Типаж генератора кода

### Шаги разработки плагина

#### 1. Создание проекта плагина

Создайте новый проект Rust и добавьте зависимости от `xcell-core` и `xcell-types`:

```toml
[package]
name = "xcell-my-plugin"
version = "0.1.0"
edition = "2024"

[dependencies]
xcell-core = { path = "../xcell-core" }
xcell-types = { path = "../xcell-types" }
```

#### 2. Реализация типажа плагина

Реализуйте соответствующие типажи по необходимости. Например, реализуйте пользовательский обработчик таблиц:

```rust
use xcell_core::x_table::table::CalamideTable;
use xcell_errors::XResult;

pub struct MyCustomTable;

impl MyCustomTable {
    pub fn confirm(table: &CalamideTable) -> XResult<Self> {
        todo!("Проверьте, соответствует ли таблица пользовательскому формату")
    }

    pub fn perform(&self, workspace: &mut WorkspaceManager) -> XResult<()> {
        todo!("Выполните логику обработки таблицы")
    }
}
```

#### 3. Регистрация плагина

Зарегистрируйте ваш плагин в методе `WorkspaceManager::try_perform_file()`, чтобы он мог быть распознан и обработан.

### Лучшие практики разработки плагинов

1. **Держите плагины независимыми**: Плагины должны быть максимально независимыми, уменьшая зависимости от внутренней реализации XCell
2. **Предоставляйте параметры конфигурации**: Предоставляйте конфигурацию плагина через `XCell.toml`
3. **Обработка ошибок**: Правильно обрабатывайте ошибки, предоставляйте понятные сообщения об ошибках
4. **Документация**: Предоставляйте полную документацию по использованию плагинов
5. **Тестирование**: Пишите достаточное количество тестовых случаев

## Резюме

XCell предоставляет мощную расширяемость, позволяя разработчикам настраивать функциональность в соответствии с их потребностями. Независимо от того, добавляете ли вы новые типы данных, расширяете генераторы кода или разрабатываете независимые плагины, модульная архитектура XCell может хорошо поддерживать эти потребности.

Если вы столкнулись с проблемами при расширении, обратитесь к исходному коду проекта или отправьте Issue для получения помощи.
