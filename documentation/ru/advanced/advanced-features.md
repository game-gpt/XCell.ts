## Расширенные параметры конфигурации

Файл конфигурации XCell `XCell.toml` предоставляет богатые параметры конфигурации, позволяя гибко настраивать поведение инструмента.

### Базовая структура конфигурации

Полный файл конфигурации `XCell.toml` содержит следующие основные части:

```toml
version = "0.0.0"

exclude = ""
include = "*.xlsx"

line.field = 1
line.type = 2
line.comment = 3
line.data = 4

[type.bool]
accept = ["true", "√"]
reject = ["false", "x"]

[type.string]

[merge]
```

### Конфигурация управления версиями

```toml
version = "0.0.0"
```

- **version**: Номер текущей версии проекта, используется для идентификации версии сгенерированного кода и файлов данных

### Конфигурация включения/исключения файлов

```toml
exclude = ""
include = "*.xlsx"
```

- **include**: Шаблон файлов Excel для включения, поддерживает подстановочные знаки
- **exclude**: Шаблон файлов Excel для исключения, приоритет ниже, чем у include

Пример:
```toml
include = "tables/**/*.xlsx"
exclude = "tables/temp/*.xlsx"
```

### Конфигурация строк таблицы

```toml
line.field = 1
line.type = 2
line.comment = 3
line.data = 4
```

- **line.field**: Номер строки, где расположены имена полей (начиная с 1)
- **line.type**: Номер строки, где расположены объявления типов
- **line.comment**: Номер строки, где расположены комментарии
- **line.data**: Номер строки, с которой начинаются данные

### Конфигурация типов

#### Конфигурация логического типа

```toml
[type.bool]
accept = ["true", "√"]
reject = ["false", "x"]
```

- **accept**: Список значений, распознаваемых как true
- **reject**: Список значений, распознаваемых как false

#### Конфигурация строкового типа

```toml
[type.string]
# Расширяемая конфигурация
```

## Подробные правила слияния таблиц

Правила слияния таблиц позволяют объединять несколько таблиц Excel в одну, поддерживая слияние по строкам или столбцам.

### Конфигурация правил слияния

Правила слияния настраиваются в секции `[merge]`, каждое правило использует уникальный номер в качестве идентификатора.

```toml
[merge.10001]
mode = "row"
input = "Language_CN*"
target = "Language_CN"

[merge.10002]
mode = "row"
input = "Language_EN*"
target = "Language_EN"

[merge.20001]
mode = "column"
input = "Language*"
target = "Language"
```

### Режимы слияния

#### Режим слияния по строкам (row)

```toml
mode = "row"
```

Слияние по строкам объединяет строки данных из нескольких таблиц в одну. Подходит для:
- Больших таблиц, которые нужно разделить для управления
- Раздельного управления многоязычными данными

Пример структуры директории:
```
LanguageTable/
  - CN/
    - Language_CN_UI.xlsx
    - Language_CN_Item.xlsx
  - EN/
    - Language_EN_UI.xlsx
    - Language_EN_Item.xlsx
```

#### Режим слияния по столбцам (column)

```toml
mode = "column"
```

Слияние по столбцам объединяет столбцы из нескольких таблиц в одну. Подходит для:
- Распределения данных столбцов по разным файлам
- Совместной работы разных команд над разными частями одной таблицы

### Параметры правил слияния

- **mode**: Режим слияния, `row` или `column`
- **input**: Шаблон входных файлов, поддерживает подстановочные знаки
- **target**: Имя целевой таблицы

### Порядок выполнения слияния

Номера правил определяют порядок выполнения слияния, меньшие номера выполняются раньше. Рекомендации:
- Слияние по строкам использует диапазон 10000-19999
- Слияние по столбцам использует диапазон 20000-29999
- Другие пользовательские правила используют более высокие номера

## Советы по оптимизации производительности

### Оптимизация обработки больших таблиц

#### 1. Разумное разделение больших таблиц

- Разделяйте большие таблицы по функциям или модулям
- Используйте правила слияния по строкам для объединения при сборке
- Поддерживайте удобство сопровождения во время разработки и производительность во время выполнения

#### 2. Использование бинарного формата

- Бинарный формат имеет самую высокую скорость загрузки
- Бинарный формат рекомендуется для производственных сред
- XML/JSON можно использовать в средах разработки для отладки

### Оптимизация инкрементальных обновлений

#### 1. Режим наблюдения

Используйте режим наблюдения:

```bash
xcell.exe --watch
```

Особенности режима наблюдения:
- Регенерация только изменённых файлов
- Значительное повышение эффективности разработки
- Поддержка предварительного просмотра в реальном времени

#### 2. Разумная конфигурация наблюдения

Настройте разумные шаблоны include/exclude для уменьшения количества наблюдаемых файлов.

### Оптимизация памяти

#### 1. Загрузка только необходимых таблиц

В соответствии с API различных движков загружайте только таблицы, необходимые для текущей сцены или функции, избегайте загрузки всех таблиц сразу.

#### 2. Своевременная выгрузка

Когда определённые таблицы больше не нужны, своевременно выгружайте их для освобождения памяти.

### Оптимизация сборки

#### 1. Параллельная обработка

XCell поддерживает параллельную обработку нескольких файлов, значительно ускоряя сборку.

#### 2. Механизм кэширования

Разумно используйте кэширование, чтобы избежать повторной обработки.
