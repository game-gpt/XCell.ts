# Интеграция с JSON

> ✅ **Доступно**: Генератор данных JSON в настоящее время доступен и поддерживает генерацию файлов данных в стандартном формате JSON.

XCell поддерживает экспорт конфигурационных таблиц в формат JSON — универсальный формат обмена данными, который легко анализируется различными языками и платформами.

## Маппинг типов

| Тип XCell | Тип JSON | Описание |
|-----------|----------|------|
| `bool` | `boolean` | Логическое значение |
| `i8` | `number` | 8-битное знаковое целое |
| `i16` | `number` | 16-битное знаковое целое |
| `i32` | `number` | 32-битное знаковое целое |
| `i64` | `number` | 64-битное знаковое целое |
| `u8` | `number` | 8-битное беззнаковое целое |
| `u16` | `number` | 16-битное беззнаковое целое |
| `u32` | `number` | 32-битное беззнаковое целое |
| `u64` | `number` | 64-битное беззнаковое целое |
| `f32` | `number` | 32-битное число с плавающей точкой |
| `f64` | `number` | 64-битное число с плавающей точкой |
| `string` | `string` | Строка |
| `array<T>` | `T[]` | Массив |
| `list<T>` | `T[]` | Список |
| `map<K, V>` | `object` | Объект-отображение |
| `enum` | `string` | Имя перечисления |
| `struct` | `object` | Объект структуры |
| `color` | `string` | Цвет (шестнадцатеричный, например "#FF0000") |
| `vec2` | `object` | `{ "x": 0, "y": 0 }` |

## Параметры конфигурации

В файле `ProjectSettings.toml` конфигурация интеграции JSON расположена в секции `[json]`:

```toml
[json]
enable = true
output = "output/json"             # Директория вывода данных JSON
indent = 2                         # Пробелы отступа (0 для компактного формата)
```

## Формат вывода

### Формат таблицы List

Таблицы List экспортируются как массивы JSON:

```json
[
  {
    "id": 1,
    "name": "Меч",
    "damage": 100,
    "price": 500,
    "is_active": true
  },
  {
    "id": 2,
    "name": "Щит",
    "damage": 0,
    "price": 300,
    "is_active": true
  }
]
```

### Формат таблицы Dictionary

Таблицы Dictionary экспортируются как объекты JSON с первичными ключами в качестве ключей:

```json
{
  "1": {
    "id": 1,
    "name": "Меч",
    "damage": 100,
    "price": 500
  },
  "2": {
    "id": 2,
    "name": "Щит",
    "damage": 0,
    "price": 300
  }
}
```

### Формат таблицы Enum

Таблицы Enum экспортируются как объекты JSON:

```json
{
  "enum_name": "ItemType",
  "values": {
    "WEAPON": 1,
    "ARMOR": 2,
    "CONSUMABLE": 3
  }
}
```

### Примеры сложных типов

#### Тип массива

```json
{
  "id": 1,
  "name": "Набор навыков",
  "skills": [101, 102, 103]
}
```

#### Тип структуры

```json
{
  "id": 1,
  "name": "Игрок",
  "position": {
    "x": 100.0,
    "y": 200.0,
    "z": 50.0
  }
}
```

#### Тип отображения

```json
{
  "id": 1,
  "name": "Локализация",
  "translations": {
    "en": "Hello",
    "zh": "你好",
    "ja": "こんにちは"
  }
}
```

## Варианты использования

### Фронтенд-приложения

Формат JSON хорошо подходит для фронтенд-приложений:

```typescript
// Загрузка данных JSON
async function loadItemData(): Promise<Item[]> {
  const response = await fetch('/data/items.json');
  return response.json();
}
```

### Бэкенд-сервисы

В Node.js или других бэкенд-средах:

```javascript
const fs = require('fs');
const items = JSON.parse(fs.readFileSync('./output/json/items.json', 'utf-8'));
```

### Игровые движки

Большинство игровых движков поддерживают разбор JSON:

- **Unity**: `JsonUtility.FromJson<T>()`
- **Cocos**: `JSON.parse()`
- **Unreal**: Использование плагина JSON

## Примечания

### Точность чисел

Типы чисел JSON не различают целые числа и числа с плавающей точкой. Возможна потеря точности для 64-битных целых чисел. Если необходимо точно представить большие целые числа, рекомендуется использовать строковые типы.

### Кодировка

Файлы JSON используют кодировку UTF-8 по умолчанию. Обеспечьте корректную обработку символов Unicode.

### Размер файла

Для больших конфигурационных таблиц файлы JSON могут быть довольно большими. Рассмотрите:

1. Использование компактного формата (установите `indent = 0`)
2. Включение сжатия GZIP для передачи
3. Использование бинарных форматов (например, MessagePack) в качестве альтернативы

## Лучшие практики

1. **Управление версиями**: Включите сгенерированные JSON файлы в управление версиями для отслеживания изменений
2. **Валидация данных**: Используйте JSON Schema для проверки формата данных
3. **Ленивая загрузка**: Загружайте данные по требованию для уменьшения времени начальной загрузки
4. **Кэширование**: Кэшируйте загруженные данные, чтобы избежать повторного разбора
