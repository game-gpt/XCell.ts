# Интеграция с SQL

> ⚠️ **В разработке**: Генератор кода SQL в настоящее время находится в разработке, функциональность может быть неполной.

XCell поддерживает экспорт конфигурационных таблиц в формат SQL для инициализации баз данных и миграции данных.

## Текущий статус

Генератор кода SQL (`sql`) в настоящее время находится в разработке, поддерживая базовую функциональность генерации SQL.

## Маппинг типов

| Тип XCell | Тип SQL | Описание |
|-----------|---------|------|
| `bool` | `BOOLEAN` | Логическое значение |
| `i8` | `TINYINT` | 8-битное знаковое целое |
| `i16` | `SMALLINT` | 16-битное знаковое целое |
| `i32` | `INT` | 32-битное знаковое целое |
| `i64` | `BIGINT` | 64-битное знаковое целое |
| `u8` | `TINYINT UNSIGNED` | 8-битное беззнаковое целое |
| `u16` | `SMALLINT UNSIGNED` | 16-битное беззнаковое целое |
| `u32` | `INT UNSIGNED` | 32-битное беззнаковое целое |
| `u64` | `BIGINT UNSIGNED` | 64-битное беззнаковое целое |
| `f32` | `FLOAT` | 32-битное число с плавающей точкой |
| `f64` | `DOUBLE` | 64-битное число с плавающей точкой |
| `string` | `VARCHAR(n)` | Строка переменной длины |
| `text` | `TEXT` | Длинный текст |
| `array<T>` | `JSON` | Массив JSON |
| `map<K, V>` | `JSON` | Объект JSON |
| `enum` | `VARCHAR(64)` | Имя перечисления |

## Параметры конфигурации

В файле `ProjectSettings.toml` конфигурация интеграции SQL расположена в секции `[sql]`:

```toml
[sql]
enable = true
output = "output/sql"             # Директория вывода SQL файлов
database = "mysql"                # Тип базы данных
schema_name = "game_data"         # Имя базы данных
create_table = true               # Генерировать ли операторы CREATE TABLE
insert_data = true                # Генерировать ли операторы INSERT
drop_table = false                # Генерировать ли операторы DROP TABLE
```

## Формат вывода

### Операторы создания таблиц

```sql
-- Таблица предметов
CREATE TABLE IF NOT EXISTS `item` (
  `id` INT NOT NULL PRIMARY KEY,
  `name` VARCHAR(255) NOT NULL,
  `damage` INT DEFAULT 0,
  `price` INT DEFAULT 0,
  `is_active` BOOLEAN DEFAULT TRUE,
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### Операторы вставки

```sql
-- Данные предметов
INSERT INTO `item` (`id`, `name`, `damage`, `price`, `is_active`) VALUES
  (1, 'Меч', 100, 500, TRUE),
  (2, 'Щит', 0, 300, TRUE),
  (3, 'Зелье', 0, 50, TRUE);
```

### Полный пример

```sql
-- ============================================
-- SQL, сгенерированный XCell
-- База данных: game_data
-- Время генерации: 2024-01-01 00:00:00
-- ============================================

-- Таблица игроков
CREATE TABLE IF NOT EXISTS `player` (
  `id` INT NOT NULL PRIMARY KEY,
  `name` VARCHAR(255) NOT NULL,
  `level` INT DEFAULT 1,
  `gold` BIGINT DEFAULT 0,
  `is_active` BOOLEAN DEFAULT TRUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Данные игроков
INSERT INTO `player` (`id`, `name`, `level`, `gold`, `is_active`) VALUES
  (1, 'Алиса', 10, 1000, TRUE),
  (2, 'Борис', 5, 500, TRUE);

-- Таблица предметов
CREATE TABLE IF NOT EXISTS `item` (
  `id` INT NOT NULL PRIMARY KEY,
  `name` VARCHAR(255) NOT NULL,
  `damage` INT DEFAULT 0,
  `price` INT DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Данные предметов
INSERT INTO `item` (`id`, `name`, `damage`, `price`) VALUES
  (1, 'Меч', 100, 500),
  (2, 'Щит', 0, 300);
```

## Варианты использования

### Инициализация базы данных

Используйте сгенерированные SQL файлы для инициализации базы данных:

```bash
mysql -u root -p game_data < output/sql/init.sql
```

### Миграция данных

Используйте SQL файлы для миграции данных:

```bash
# Экспорт данных
mysqldump -u root -p game_data > backup.sql

# Импорт данных
mysql -u root -p game_data < output/sql/init.sql
```

### Управление версиями

Включите SQL файлы в управление версиями для отслеживания истории изменений данных.

## Примечания

### Длина строк

Тип `VARCHAR` в SQL требует указания длины. XCell автоматически выведет подходящую длину на основе данных, или вы можете указать длину по умолчанию в конфигурации.

### Ограничения первичного ключа

XCell автоматически идентифицирует поля первичного ключа и добавляет ограничения `PRIMARY KEY`.

### Индексы

Текущая версия не автоматически генерирует индексы. Если нужны индексы, добавьте их вручную или используйте инструменты управления базами данных.

### Транзакции

Для больших вставок данных рекомендуется оборачивать в транзакции:

```sql
START TRANSACTION;
INSERT INTO `item` (`id`, `name`) VALUES (1, 'Меч');
INSERT INTO `item` (`id`, `name`) VALUES (2, 'Щит');
COMMIT;
```

## Лучшие практики

1. **Резервное копирование**: Убедитесь, что существующие данные скопированы перед выполнением SQL файлов
2. **Тестовая среда**: Сначала проверьте SQL файлы в тестовой среде
3. **Управление версиями**: Включите SQL файлы в управление версиями
4. **Инкрементальные обновления**: Для производственных сред рекомендуется использовать инкрементальные обновления вместо полной перезаписи
