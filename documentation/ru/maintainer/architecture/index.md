# Документ по архитектурному дизайну XCell

## 1. Общий обзор архитектуры проекта

XCell — это инструмент управления конфигурационными таблицами, написанный на Rust, использующий модульный дизайн с чётким разделением ответственности модулей и слабой связностью. Проект разделён на следующие основные части:

- **Бэкенд-модули**: Расположены в директории `backends/`, содержат основную бизнес-логику
  - `xcell` - Инструмент командной строки и основная точка входа
  - `xcell-analyzer` - Управление рабочим пространством и анализ таблиц
  - `xcell-generator` - Генератор кода
  - `xcell-provider` - Абстракция чтения таблиц
  - `xcell-core` - Система типов и базовая функциональность
  - `xcell-config` - Управление конфигурацией
  - `xcell-macros` - Определения макросов
  - `xcell-parser` - Парсер типов
  - `xcell-plugin` - Система плагинов
  - `xcell-wasi` - Поддержка WebAssembly

- **Фронтенд-модули**: Расположены в директории `frontends/`, содержат пользовательские интерфейсы
  - `homepage` - Официальный сайт проекта
  - `xcell` - Фронтенд SDK
  - `xcell-desktop` - Десктопное приложение
  - `xcell-h5` - Веб-приложение

- **Документация**: Расположена в директории `documentation/`, содержит документацию проекта

- **Примеры**: Расположены в директории `examples/`, содержат примеры использования

### Технологический стек

- **Бэкенд**: Rust
- **Фронтенд**: Vue.js, TypeScript, Tauri
- **Чтение таблиц**: calamine (Excel), csv (CSV/TSV)
- **Шаблонизатор**: dejavu
- **Асинхронная среда выполнения**: tokio
- **Обработка ошибок**: anyhow
- **Логирование**: tracing

## 2. Разделение модулей и описание ответственности

### 2.1 xcell - Инструмент командной строки

**Ответственность**:
- Предоставление интерфейса командной строки
- Разбор аргументов командной строки
- Координация всего рабочего процесса
- Вызов других бэкенд-модулей для выполнения задач

**Основные файлы**:
- `backends/xcell/src/main.rs` - Точка входа программы
- `backends/xcell/src/workspace.rs` - Управление рабочим пространством
- `backends/xcell/src/commands/toml.rs` - Обработка конфигурации TOML

**Основные функции**:
- Генерация кода и файлов данных
- Проверка конфигурации
- Очистка вывода
- Режим наблюдения за файлами

### 2.2 xcell-analyzer - Управление рабочим пространством и анализ таблиц

**Ответственность**:
- Управление рабочим пространством и конфигурацией
- Сканирование и идентификация файлов таблиц
- Разбор данных таблиц
- Идентификация типов таблиц
- Обработка данных таблиц
- Привязка определений перечислений

**Основные файлы**:
- `backends/xcell-analyzer/src/lib.rs` - Экспорт модуля
- `backends/xcell-analyzer/src/config/mod.rs` - Менеджер рабочего пространства
- `backends/xcell-analyzer/src/x_table/mod.rs` - Структуры данных таблиц

**Основные компоненты**:
- `WorkspaceManager` - Менеджер рабочего пространства, отвечает за координацию всего рабочего процесса
- `XClassTable` - Тип таблицы Class
- `XDictTable` - Тип таблицы Dictionary
- `XEnumerateTable` - Тип таблицы Enum
- `XLanguageTable` - Тип таблицы Language
- `DefineManager` - Менеджер определений перечислений
- `LanguageManager` - Менеджер таблиц языков

### 2.3 xcell-generator - Генератор кода

**Ответственность**:

## 3. Описание потока данных

### 3.1 Общий процесс

Полный процесс от чтения файла таблицы до экспорта кода:

```
Файл таблицы (Excel/CSV/TSV) → Чтение/Разбор → Распознавание таблицы → Обработка данных → Генерация кода → Выходные файлы
```

### 3.2 Подробные шаги

#### Шаг 1: Инициализация рабочего пространства

1. Разбор аргументов командной строки или файла конфигурации
2. Создание экземпляра `WorkspaceManager`
3. Загрузка конфигурации проекта (`ProjectConfig`)

#### Шаг 2: Сканирование файлов

1. Сканирование рабочей директории
2. Использование `WalkDir` для обхода директории
3. Фильтрация файлов по настроенному шаблону `include`

#### Шаг 3: Чтение файлов таблиц

1. Использование функции `load_table()` для чтения файлов таблиц (автоопределение формата)
2. Разбор заголовка таблицы (`XCellHeader`)
3. Чтение всех строк данных

#### Шаг 4: Идентификация типа таблицы

Попытка идентификации следующих типов таблиц по порядку:

1. `XListTable` - Таблица List
2. `XDictTable` - Таблица Dictionary
3. `XEnumerateTable` - Таблица Enum
4. `XClassTable` - Таблица Class
5. `XLanguageTable` - Таблица Language
6. `XLanguageID` - Таблица ID языков

#### Шаг 5: Обработка данных таблицы

Выполнение соответствующих операций в зависимости от типа таблицы:

- Для таблиц enum: Добавление в `DefineManager`
- Для таблиц языков: Добавление в `LanguageManager`
- Для других таблиц: Выполнение валидации данных и сохранение

#### Шаг 6: Привязка перечислений

Вызов метода `link_enumerate()` для привязки определений перечислений к соответствующим полям данных

#### Шаг 7: Генерация кода

1. Создание экземпляра `Generator`
2. Настройка включённых генераторов кода
3. Итерация по всем включённым выводам
4. Вызов соответствующего генератора кода для каждого вывода
5. Генерация кода и файлов данных в соответствующих форматах

#### Шаг 8: Наблюдение за файлами (опционально)

Если наблюдение за файлами включено:
1. Запуск наблюдателя файлов
2. Ожидание изменений файлов
3. Автоматическая повторная обработка изменённых файлов

## 5. Дизайн изоляции абстракций

### 5.1 Основные уровни абстракции

XCell использует многоуровневый дизайн абстракций, обеспечивая чёткое разделение ответственности модулей и предотвращая утечку абстракций:

1. **Уровень чтения таблиц** (`xcell-provider`):
   - Предоставляет унифицированный типаж `TableReader`
   - Абстрагирует различия между форматами таблиц (Excel, CSV, TSV)
   - Верхние модули не должны знать о конкретных форматах таблиц

2. **Уровень анализа таблиц** (`xcell-analyzer`):
   - Читает данные таблиц на основе `TableReader`
   - Идентифицирует типы таблиц и выполняет соответствующую обработку
   - Предоставляет `WorkspaceManager` для унифицированного управления всеми данными таблиц

3. **Уровень генерации кода** (`xcell-generator`):
   - Получает данные таблиц на основе `WorkspaceManager`
   - Не взаимодействует напрямую с файлами таблиц
   - Поддерживает несколько генераторов кода через типаж `Codegen`

4. **Уровень системы типов** (`xcell-core`):
   - Определяет унифицированные типы данных
   - Предоставляет преобразование и разбор типов
   - Поддерживает маппинг типов для нескольких платформ

### 5.2 Принципы изоляции абстракций

- **Единая ответственность**: Каждый модуль отвечает только за одну конкретную функцию
- **Инверсия зависимостей**: Высокоуровневые модули зависят от абстракций, а не от конкретных реализаций
- **Разделение интерфейсов**: Использование типажей для определения минимальных интерфейсов
- **Принцип подстановки Барбары Лисков**: Реализации могут быть заменены их подтипами
- **Принцип открытости/закрытости**: Открыты для расширения, закрыты для модификации

## 6. Руководство по расширению

### Добавление нового формата таблиц

1. Создайте новую реализацию чтения таблиц в `backends/xcell-provider/src/table/`
2. Реализуйте типаж `TableReader`
3. Добавьте логику обнаружения формата в `FileFormatDetector`
4. Добавьте поддержку нового формата в функцию `load_table`

### Добавление нового типа данных

1. Создайте новый модуль в `backends/xcell-core/src/`
2. Реализуйте логику разбора и преобразования типа
3. Экспортируйте в `backends/xcell-core/src/lib.rs`
4. Добавьте поддержку маппинга типов для соответствующих платформ

### Добавление нового генератора кода

1. Создайте новый модуль в `backends/xcell-generator/src/codegen/`
2. Реализуйте типаж `Codegen`
3. Зарегистрируйте новый генератор в `Generator::new()`
4. Добавьте соответствующие параметры конфигурации

### Добавление поддержки новой платформы

1. Создайте новый модуль конфигурации платформы в `backends/xcell-config/src/`
2. Создайте новый генератор кода платформы в `backends/xcell-generator/src/codegen/`
3. Реализуйте специфичную для платформы логику генерации кода
4. Обновите документацию и примеры
